# 描画の設計

[English](DESIGN.md) | 日本語 · [READMEへ戻る](../README.ja.md)

波形・再生位置線・拍グリッド・キューを、共通の時間軸で描画します。音声の再生状態は利用側で管理し、レンダラーには各フレームの表示に必要な値を渡します。

## 1フレームの入力を一度確定する

`WaveformRenderer`は、メインActor上で1フレームの入力を一度取得します。`timedFrameInputProvider`が設定されていれば表示予定のホスト時刻を渡し、未設定なら従来の`frameInputProvider`を呼びます。

音声クロックから求めた再生位置を、ズーム・キュー時刻とまとめて返してください。再生状態は利用側が持ちます。

### ホスト時刻と再生位置

`WaveformMetalView`は、`CADisplayLink.targetTimestamp`を`draw(in:atHostTime:)`へ渡します。この時刻は`CACurrentMediaTime()`と同じ基準であり、トラック先頭からの秒数ではありません。

表示予定のホスト時刻を、音声クロックの再生位置へ変換します。計算には、同じ瞬間を表すホスト時刻と再生位置の組、および再生速度を使います。[コード例](GETTING_STARTED.ja.md#音声の再生位置と連動させる)を参照してください。

従来の`draw(in:)`は現在の`CACurrentMediaTime()`を使います。明示的に渡したホスト時刻が有限値でない場合も、現在の時刻で補います。

### 共通の座標変換

波形・拍グリッド・キューは、一つの表示範囲とスナップ済みの`ViewportUniforms`を共有します。概念的な座標変換は次のとおりです。

```text
x = (time - visibleStart) / visibleDuration * drawableWidth
```

GPUではFloatを使い、カメラ位置をピクセル単位の整数部と小数部に分けて、`fma`で座標を求めます。CPUの座標計算はDoubleを使うため、両者の計算結果がビット単位で一致する保証はありません。

### 再生位置線とピクセルスナップ

既定の同期モードでは、再生線の幾何学的な中心を画面中央に固定します。波形・グリッド・キュー側では、スナップによって座標が丸められます。

再生線が示す時刻をこの座標変換で描いた位置は、再生線の中心から最大0.5描画ピクセルずれます。これに浮動小数点演算やラスタライズの許容差が加わります。

この上限は座標変換の差を表し、LODの区間内にある振幅の極値の時刻までは保証しません。古い再生位置を使う比較モードでは再生線が中央から動くため、この上限の対象外です。

## 解析とバッファ生成を毎フレームの処理から分ける

| タイミング | 処理 |
| --- | --- |
| トラックごとに一度 | PCMの最小値・最大値を集約し、複数解像度のLODを構築 |
| 各LODを初めて使うとき | 時刻・振幅の頂点と`MTLBuffer`を生成して保持 |
| 毎フレーム | 入力取得、LOD選択、可視範囲計算、uniform更新、描画命令の発行 |

### LODと表示の細かさ

LOD（Level of Detail）は、描画の細かさを切り替えるためのデータです。最も細かいレベルでも32サンプルを一つの区間として扱い、粗いレベルは細かい区間の振幅上下限を包含します。

極値の厳密な時刻は保存しません。ズームによって形状の細かさは変わります。

### バッファの再利用

描画するのは可視範囲と境界の余裕に含まれる区間です。一度使ったLODのバッファは再利用し、`analysis`を設定し直すと全レベルのキャッシュを破棄します。各LODを初めて使うフレームではバッファ生成が発生します。

表示範囲をGPUへ渡すuniformは32バイトです。毎フレームの処理には、この更新のほか、マーカー・色の更新、可視範囲の計算、描画命令の発行も含まれます。

## 拍とキューは渡された時刻に描く

拍グリッドは曲頭を拍0とし、一定間隔で描きます。任意の拍の原点や可変テンポは初期APIの対象外です。

独立した`BeatGrid`は秒単位の計算だけを行い、BPM検出や音声の予約実行を行いません。キューも渡された時刻にマーカーを描くだけです。

## 表示更新とビューのライフサイクルを管理する

### iOSの描画更新

iOSの`WaveformSwiftUI`は、レンダラーのMSAA数に合わせて`MTKView`を作ります。ビューが持つ`CADisplayLink`から`MTKView.draw()`を呼び、delegate経由で表示予定時刻を渡します。

`isPaused = true`と`enableSetNeedsDisplay = false`で内部タイマーを止め、二重の描画更新を避けます。display linkはrun loopのcommonモードで動かすため、ジェスチャ中も更新を続けます。

### 停止・復帰とリソースの保持

ウィンドウから外れたときや、アプリまたは表示先のsceneが非アクティブになったときに描画を停止します。再接続・復帰時はdisplay linkを作り直し、新しい表示予定時刻を使います。

破棄時にはdisplay linkと通知監視を解除します。コールバック先は弱参照にして循環参照を避けています。

利用側でレンダラーを保持し、入力を設定してください。SwiftUIの更新時にレンダラーを交換でき、音源だけを変える場合は`analysis`の差し替えで済みます。

### 画面の変更とフレームレート

ビューは所属するウィンドウの画面を使い、画面が変わればdisplay linkを作り直します。その画面の最大fpsを要求しますが、実際の更新頻度はOS・画面・電力・温度・描画負荷に左右されます。

> **補足:** ProMotionでも120 fpsを保証しません。

サンプルは`RenderingDemo-Info.plist`で`CADisableMinimumFrameDurationOnPhone`を有効にしています。ライブラリを組み込むアプリでは自身の設定を選んでください。この設定だけでfpsが保証されるわけではありません。

### macOSでの接続

macOSでは、利用側で`MTKView`を用意し、次の値を設定します。

- `colorPixelFormat = .bgra8Unorm`
- `sampleCount = WaveformRenderer.rasterSampleCount`
- `delegate = renderer`

レンダラーと同じMetalデバイスを使い、レンダラーを強参照で保持します。

内部の`encodeFrame`は、表示用ビューとオフスクリーンテストが共有する処理です。画像書き出し用の公開APIではありません。

## 比較用の設定と計測値

通常利用では既定値を使います。次の設定は、描画動作を比較するためのものです。

| 設定 | 比較する動作 |
| --- | --- |
| `rebuildEveryFrame` | バッファの毎フレーム再構築 |
| `playheadProjection` | 古い再生位置などを使った投影 |
| `unsnappedCamera` | カメラのピクセルスナップの有無 |

ピクセルスナップは縁の明滅を抑えられますが、非常に遅い移動では段階的に進んで見える場合があります。

### 見た目の明滅とフレームの欠落

表示予定時刻を使い、再生線を固定しても、細かな動きをフレームごとに表示することで別の動きに見える「時間方向のエイリアシング」は残ります。高倍率ではサンプルの110 Hzの波が見分けやすくなるため、フレームが等間隔でも明滅や不均一な動きに見える場合があります。

この見た目だけではフレームの欠落と判定できません。描画タイミングは別途確認してください。

### 計測値で確認できる範囲

`RenderStats`のCPU時間はGPU完了やスピーカー出力までの時間を含みません。再生線のずれはCPU上の投影結果を比較した値であり、描画画像の独立した検証にはGPU画像テストを使います。

一定のfpsや音声との同期精度は、この計測からは判断できません。

画像テストの条件と許容範囲は[GPUテストのソースコード](../Tests/WaveformMetalGPUTests/)で確認できます。
